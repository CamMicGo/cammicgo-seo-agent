# CamMicGo SEO MCP Android — experimental APK (v0.2.0)

On-device YouTube transcript extraction. The request leaves the phone, from its residential IP, which avoids the `LOGIN_REQUIRED` / "confirm you're not a bot" block YouTube applies to cloud servers such as Vercel. It is **not yet synchronized with the remote MCP**: no pairing, background service or upload is implemented. Never advertise it as synchronized.

## How it works
1. Share a YouTube URL to the app (or paste it), choose a preferred language (`en` by default).
2. `TranscriptFetcher` tries, in order:
   - the InnerTube player endpoint with the **ANDROID** client (its caption URLs do not need the web `pot` token);
   - the `ytInitialPlayerResponse` embedded in the watch page (fallback).
   A consent cookie (`SOCS`) is sent so EU devices are not redirected to `consent.youtube.com`.
3. Track choice: requested language (manual, then auto-generated), then the original-audio track, then the first track.
4. Output: `[mm:ss] text` lines, plus **Copy**, **JSON** and **Share**. The JSON has the same shape as the MCP `youtube_get_transcript` success response (`videoId`, `language`, `isAutoGenerated`, `availableLanguages`, `segments[{start,duration,text}]`), ready for future synchronization.

Failures list each attempted method and YouTube's `playabilityStatus` / reason.

## Build
GitHub Actions workflow **Build CamMicGo Android APK** builds a debug-signed APK on every push touching `android-kamiko/`, uploads it as an artifact and, on `main`, publishes it to the `android-test-latest` pre-release served by `/download/android/apk`. Local build: Android SDK 35, JDK 17, Gradle 8.9, then `gradle :app:assembleDebug` from this directory.

The launcher icons in `app/src/main/res/mipmap-*` are generated from the dedicated APK logo (`public/branding/cammicgo-seo-mcp-apk-icon.png`); the workflow no longer regenerates them from `public/logo.svg`.
